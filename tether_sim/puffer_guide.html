Train your drone with PufferLib

You already have a controller trained with Stable Baselines3. We are transferring its weights, optimizer state and observation statistics into PufferLib 3. The simulator remains the Crazyflie tether model with obstacles.

CPU simulator → observation → CUDA policy → four motor corrections → CPU simulator
Experiences → CUDA advantage calculation → CUDA policy update → saved checkpoint

1. What is the drone learning?

A geometric planner chooses a route around known obstacles. A PD controller tries to follow that route. The learned policy adds a small correction to each of the four motor commands. It is learning disturbance compensation, not camera-based obstacle recognition.

2. Understand one step

The simulator reports an observation: positions, velocities, cable state, motor thrust, target and domain variables. The policy samples four corrections between -1 and 1. Each correction is scaled by 0.03 and added to the PD command. Ten 2 ms physics substeps advance 20 ms of flight. The task then returns a reward and whether the episode ended.

4. What is PPO doing?

A critic predicts the future reward from the current state. Advantage estimates how an action turned out relative to that prediction. PPO adjusts the probability of actions using these estimates, with clipping intended to limit large policy changes. PufferLib 3 uses its own PPO variant; its results are not an exact continuation of SB3's algorithm.

5. Watch it in this app

Select tether_puffer_cuda_v002 in the run list. Device should say cuda and the step counter should advance after initial evaluation. Train PufferLib starts another bounded run when no trainer is active. Play selected policy loads a completed exported checkpoint into a separate simulator preview. The moving preview is not a live image of the training batch.

6. Decide whether it improved

Steps per second measures throughput. Reward measures the trainer's objective. Held-out success rate, collisions and final payload error tell you whether the drone task improved. A success requires reaching the destination, payload error below 8 cm, swing below 10 degrees and no crash. Look at those metrics before trusting a higher reward.

7. Run it yourself in Ubuntu-Laya

cd /home/n33du/ai/drone-rl-lab
bash scripts/run_tether_puffer.sh --config configs/tether_puffer_cuda_v002.json --output tmp/tether-runs/my_puffer_run

Use a new output name each time. Start with the existing settings. For your next experiment, copy the configuration to a new file and change one setting, such as worker count. Keep the evaluation seeds and physics fixed so the comparison is useful.

What remains limited?

This is PufferLib 3's Python-compatible path, not the native PufferLib 5 C environment port. Physics and geometry queries still take CPU time. Observation and reward statistics are frozen from the transfer. PufferLib clips training rewards to [-1,1], and our finite episode horizon is treated as terminal because this version's advantage calculation ignores separate truncations. Those are recorded experiment differences. Hardware mass, thrust and cable parameters remain uncalibrated; this app does not control the real drone.
